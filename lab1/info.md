# Как рассказывать

## Покажи структуру проекта 

### Вне папки client
Открой вначале файл main.go. Здесь каждая строчка у нас создает часть нашего приложения.
`repository := NewInMemoryRepository()` - создает наш репозиторий (некая простая база данных, которая содержится в оперативной памяти)
`service := NewOrderService(repository, repository)` - создает структуру с бизнес логикой сервиса
`handler := NewHandler(service)` - создает обработчики запросов, приходящих на сервис (то есть функции, которые вызывается, когда у нас запрос прилетает на определенный эндпоинт)
`router := SetupRoutes(handler)` - создает наш роутер. Роутер - это сервер приложения, который у нас работает на конкретном порте (8080 в нашем случае), и принимает запросы по HTTP

Под репозиторий открой файл repository.go. Вот это файлик, в котором определены все методы нашего репозитория
```go
type OrderRepository interface {
	Create(order *Order) *Order // этот метод создает заказ
	FindByID(id int) (*Order, bool)
	FindAll() []*Order
	Update(order *Order) bool
	Delete(id int) bool
}
```
полистай чуть ниже, там расписаны эти методы подробнее
если спросит про это:
```go
	r.mu.Lock()
	defer r.mu.Unlock()
```
то скажи, что это мьютекс, он защишает нашу программу от гонки данных. Гонка данных - это когда у нас несколько функций одновременно обращаются к каким то данным, изза чего могут путаться

Под сервис ну ты понял
просто читай коменты, это наша бизнес логика

под handler тоже
просто листай код и скажи, что здесь в каждой функции у нас прилетает HTTP-запрос, в ответ на него вызывается функция из бизнес-логики(`service.go`), обрабатываются возможные ошибки и затем отправляется ответ клиенту

### В папке client

`api_client.go` - здесь у нас создается подключение к сервису (который вне папки)

`main.go` - запускает то, что от нас требуется в задании

`models.go` - наши сущности.
```go
type Task struct {
	ID       int    `json:"id"` // тут в кавычках - структурный тег. Это особенность GO, которая позволяет конвертировать из JSON в GO-шную структуру
```

дальше расскажи про `optimizer.go`, это важно
```go
func (o *Optimizer) runParallelComputation(tasks []Task, taskIDs []int) Result {
	jobs := make(chan int, o.numSequences)
	results := make(chan Result, o.numSequences)

	var wg sync.WaitGroup // это паттерн Worker Pool. Он у нас распределяет входящую нагрузку на заданное количество параллельно работающих функций
	for w := 0; w < o.numWorkers; w++ {
		wg.Add(1)
		go o.worker(tasks, taskIDs, jobs, results, &wg) // тут у нас запускаются горутины в цикле - это и есть функция, которая запустится параллельно.

        // WG здесь - это WaitGroup - механизм, который позволяет дождаться завершения горутины
	}

	go func()    // вот эта функция у нас параллельно с вычислениями будет записывать результат сразу же
    { 
		for i := 0; i < o.numSequences; i++ {
			jobs <- i
		}
		close(jobs)
	}() 

	go func() // тут наша WaitGroup дожидается как раз таки, а затем закрывается канал с результатами
    {
		wg.Wait() 
		close(results)
	}()
    // Что такое канал - структура, в которую мы можем параллельно записывать данные и передавать их между горутинами

	return o.collectResults(results)
}
```

# Как запустить программу
1. В вс коде открывай папку `labs` целиком. Затем через `Ctrl + Ё` у тебя открывается терминал

2. Здесь вводи команду `cd lab1`. Для справки: `cd ..` вернет тебя на уровень выше, если запутаешься

3. Вводи команду `go run .` - она запустит твой сервис

4. Справа в терминале есть плюсик - он откроет тебе новый терминал (powershell)

5. Перейди к клиенту вводи команду `cd lab1/client`

6. Запусти работу `go run .` - это тебе запустит клиент и выполнит логику работы в нем
